# Секреты и личные данные

Адрес сервиса и ключи задаются через окружение. `.env.example` и `.env.vps.example` содержат только нейтральные примеры. Настоящие пароли, API-ключи, токены агентов, URL с временными подписями и VPN-конфигурации в исходники и задачи ChatGPT не добавлять.

Личные статьи, исходные файлы, словарь, сессии и OAuth-данные находятся в SQLite в `data/`. Каталог, резервные копии Git, логи, отчёты браузерных тестов, `.env` и файлы ключей исключены из Git и Docker build context. Локальный `.env.vps.local` предназначен для приватных настроек развёртывания; он не входит в публичный репозиторий. Копировать его на сервер отдельно защищённым способом и использовать как `.env`.

Перед публикацией проверять не только рабочие файлы, но и всю историю веток и тегов, которые будут отправлены. Удаление секрета новым коммитом не удаляет его из старого. Если настоящий ключ уже опубликован, его нужно отозвать или заменить; одной очистки истории недостаточно. Не добавлять личные идентификаторы чатов и пути к профилю пользователя.

В тестах используются явно обозначенные фиктивные пароли (`*-fixture-password`, `test-only-password`) и зарезервированные адреса. Они не используются как значения по умолчанию в production. Production требует отдельный пароль владельца и HTTPS APP_ORIGIN. Локальный режим без пароля слушает только loopback.

Перед первым push проверить `git status`, список отслеживаемых файлов и секреты. Отправлять подготовленные ветку и тег явно:

```sh
git push -u origin main
git push origin v0.2.0
```

Публикация всего каталога проекта архивом обходит `.gitignore` и может включить личные данные. Для распространения исходников использовать Git или `git archive main`. Учётная запись автора коммитов и публичные ссылки на научные статьи являются частью публикуемого проекта.
