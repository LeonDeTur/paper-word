# Paperword

Личный веб-сервис для чтения англоязычных статей с переводом и изучения слов в контексте. Работает в браузере компьютера и телефона. Основа: React, TypeScript, Node.js 24, Express и SQLite.

## Что реализовано

- Импорт готовых HTML, текстовых PDF, ссылок и вставленного текста; исходные файлы сохраняются.
- Библиотека: поиск, темы, избранное, статусы «Новая / Читаю / Прочитана», переименование и удаление.
- Читалка: RU для отдельного фрагмента, RU ALL, редактирование перевода, оглавление, части по 24 фрагмента, сохранение места чтения.
- Перевод статьи и слов через **OpenAI-совместимый API**, в том числе Ollama. Приложение не зависит от нативного API Ollama.
- Нажатие слова или выделение выражения → начальная форма, перевод, исходный контекст и заметка. При выбранной модели форма и перевод предлагаются автоматически; перед сохранением их можно исправить.
- Наведение на слово или фокус с клавиатуры сразу показывает словарный перевод из статьи без обращения к ИИ; клик открывает создание карточки. Подсказка закрывается по Escape, при уходе указателя или прокрутке.
- Дубликаты по начальной форме блокируются интерфейсом и уникальным индексом в БД. Регистр, повторные пробелы и типографские апострофы не создают отдельные записи.
- Одна словарная запись, два направления повторения: EN → RU и RU → EN, у каждого своё расписание.
- Светлая и чёрная темы, вход по паролю, серверное хранение и экспорт текстовых данных в JSON.
- Монохромная чёрная тема: чёрный фон, белый текст и серые элементы, как в готовых статьях.
- HTTP API, удалённый MCP и локальный MCP-адаптер для агента; отдельные отзываемые токены, защита от повторного импорта.

Подключение агента описано в [docs/agent-integration.md](docs/agent-integration.md). Выпуск токенов доступен в настройках.

## Быстрый локальный запуск

Нужен Node.js **24.14 или новее** с `node:sqlite`.

```powershell
npm ci
npm run setup
npm run dev
```

Открыть [http://localhost:5173](http://localhost:5173). API работает на `127.0.0.1:3001`. Без `APP_PASSWORD` сервер принудительно слушает только loopback. Библиотека при первом запуске пустая; проверочные материалы не добавляются в пользовательские данные.

`setup` не перезаписывает существующий `.env` и включает Git hooks для форматирования, типов, защиты приватных файлов и Conventional Commits. Для браузерных тестов установите Chromium: `npx playwright install chromium`. Все команды и работа на Windows/Linux описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

## CI и релизы

GitHub Actions проверяет формат, Oxlint, TypeScript, сборку, unit/integration-тесты на Linux и Windows, мобильные/настольные сценарии Playwright с проверками доступности и сборку production Docker-образа. Coverage, HTML/JUnit/trace и снимки доступны в артефактах CI. CodeQL и аудит зависимостей запускаются отдельно; Dependabot предлагает обновления без автоматического слияния.

Conventional Commits формируют версии и changelog. После успешных проверок `main` бот готовит Release PR из `chore/release`. После его слияния и повторных проверок автоматически публикуется GitHub Release с runtime-архивом и SHA-256. В npm и на VPS ничего автоматически не развёртывается. [Схема и настройки](docs/ci.md), [SemVer](docs/versioning.md).

Для просмотра собранной версии:

```powershell
npm run build
npm start
```

Открыть [http://localhost:3001](http://localhost:3001).

## Подключение Ollama или другого сервера моделей

Скопировать `.env.example` в `.env` и настроить:

```dotenv
AI_BASE_URL=http://127.0.0.1:11434/v1
AI_MODEL=имя-вашей-установленной-модели
AI_API_KEY=
```

`AI_BASE_URL` включает `/v1`. Сервис вызывает `GET /models` и `POST /chat/completions`; запросы используют `response_format: {"type":"json_object"}`. Это поддерживается OpenAI-совместимым интерфейсом Ollama: [официальная документация](https://docs.ollama.com/api/openai-compatibility).

Перезапустить API после изменения `.env`. В разделе «Настройки» проверить подключение и выбрать модель из списка или ввести точное имя вручную. Выбранная в интерфейсе модель хранится в БД и имеет приоритет над `AI_MODEL`. Модели автоматически не загружаются.

Перевод выполняется по одному фрагменту. Уже переведённые фрагменты пропускаются. Частичные результаты сохраняются после каждого ответа. После ошибки или перезапуска можно продолжить перевод. Остановка ожидает завершения текущего запроса, максимум 3 минуты. Модель должна поддерживать JSON-ответы и перевод EN → RU; качество начальной формы и перевода зависит от неё.

В Docker `127.0.0.1` обозначает контейнер приложения. Укажите адрес API, достижимый из контейнера. Для модели на том же хосте доступно имя `host.docker.internal`; сервер моделей должен принимать соединения с docker-сети. Адрес, ключ и модель настраиваются независимо от размещения самого сервиса.

## Размещение на своём VPS

Подготовлены `Dockerfile`, `compose.yaml` и Caddy для HTTPS. Понадобятся Docker с Compose и свободные порты 80/443. В `.env.vps.example` указаны нейтральные примеры: заменить домен и задать пароль. Можно использовать бесплатное DNS-имя на основе своего IPv4: [пошаговая настройка HTTPS](docs/vps-https.md).

В `.env` задать реальные значения:

```dotenv
APP_PASSWORD=длинный-уникальный-пароль-не-короче-12-символов
APP_DOMAIN=papers.example.com
APP_ORIGIN=https://papers.example.com
AI_BASE_URL=http://доступный-из-контейнера-сервер:11434/v1
AI_MODEL=имя-вашей-модели
AI_API_KEY=
```

Домен в `APP_DOMAIN` и источник в `APP_ORIGIN` должны совпадать. Затем:

```sh
docker compose up -d --build
docker compose logs -f app
```

Caddy получает TLS-сертификат и перенаправляет запросы в приложение. Порт приложения не публикуется наружу. Production-запуск отклоняется при отсутствующем/коротком пароле или отсутствии HTTPS в `APP_ORIGIN`. Сессии сохраняются в SQLite, cookie — HttpOnly, Secure и SameSite=Strict. Изменение пароля с перезапуском приложения автоматически делает старые сессии недействительными.

VPS и реальный сервер моделей в рамках локальной проверки не использовались. Сборка Docker должна быть проверена на целевом Linux-хосте.

## Данные и резервные копии

Локально БД хранится в `data/paperword.sqlite`, в Compose — в томе `paperword_data`. БД содержит статьи, исходные файлы, карточки, расписания и сессии. В SQL используются параметры, импортированный HTML преобразуется в текстовые фрагменты, его скрипты не исполняются. Загрузка по URL запрещает внутренние IP, проверяет перенаправления и закрепляет проверенный DNS-адрес.

Экспорт в настройках сохраняет статьи, переводы, карточки, расписания и события повторения в JSON. Он **не содержит исходных файлов** и не заменяет полную резервную копию. Импорт такого JSON через интерфейс пока не реализован.

Полная резервная копия Compose (Linux):

```sh
docker compose stop app
docker compose run --rm --no-deps -T app tar -C /app/data -czf - . > paperword-data.tar.gz
docker compose start app
```

Для восстановления на пустом/подготовленном томе остановить приложение, затем:

```sh
docker compose run --rm --no-deps -T app tar -C /app/data -xzf - < paperword-data.tar.gz
docker compose start app
```

Восстановление заменяет файлы из копии. Сначала сохраните текущий том. Для локального запуска достаточно остановить сервер и скопировать целиком папку `data` с SQLite/WAL-файлами, если они присутствуют.

## Интервалы повторения

Начальные интервалы: «Не помню» — 10 минут; «Трудно» — 12 часов; «Помню» — 1 день; «Легко» — 4 дня. Последующие интервалы растут с учётом успешных ответов; «Не помню» возвращает направление к обучению. Алгоритм — прозрачная вариация SM-2, а не FSRS. Направления независимы. Повторная отправка одной оценки из двух вкладок отклоняется.

Пробел раскрывает ответ, клавиши 1–4 выставляют оценку. На телефоне доступны кнопки.

## Ограничения первой версии

- Импорт проверен на реальных HTML Spatial-RAG и GeoNatureAgent Benchmark из прежней задачи: сохранены исходные файлы, английский текст, 166 и 39 переводов фрагментов и словарные подсказки. Поддержаны кнопки `.word[data-ru]`, `.article-text`, `.en` и `.ru-paragraph`. Иные шаблоны HTML могут требовать отдельной настройки.
- Из PDF извлекается текст; OCR, исходная вёрстка, математическая разметка и восстановление таблиц не реализованы. PDF остаётся доступен для скачивания. В HTML отображаются встроенные растровые изображения внутри `figure`; внешние рисунки и сложная вёрстка доступны в сохранённом оригинале.
- Импорт по ссылке получает HTML/PDF без выполнения JavaScript; закрытые и динамические сайты могут потребовать ручной загрузки.
- Перевод фрагмента свыше 12 000 символов отклоняется с предложением разделить материал.
- Офлайн-режим, Anki и многопользовательские библиотеки не реализованы.

## Проверка и структура

```sh
npm run check
npm run test:e2e
```

Браузерные тесты используют установленный Chrome и отдельную БД в памяти с подставным API. Реальные модели и личные данные не затрагиваются. Скриншоты записываются в `artifacts/qa`. Для CI без Chrome можно изменить `channel` в `playwright.config.ts` и установить браузер Playwright.

- `src/components` — библиотека, читалка, словарь, повторение и настройки.
- `server/content.ts` — разбор файлов и безопасная загрузка источников.
- `server/ai.ts` — OpenAI-совместимый клиент и проверка структуры ответов.
- `server/scheduler.ts` — расчёт интервалов.
- `server/store.ts` — SQLite и связи данных.
- `server/app.ts` — HTTP API, аутентификация и проверки входных данных.
- `docs/product-brief.md` — требования; `CONTEXT.md` — словарь предметной области.

Код форматируется `npm run format`.

## ChatGPT и версии

Поддержаны OAuth + PKCE для ChatGPT и Claude, загрузка готового файла ChatGPT через `import_chatgpt_file`, HTTP API и stdio. MCP предоставляет поиск и чтение библиотеки, изменение статей и переводов, запуск фонового перевода, создание и редактирование карточек, очередь повторений, сохранение оценок и статистику. Права выбираются в настройках и при OAuth; удаление требует отдельного разрешения и по умолчанию выключено. Старые токены сохраняют только импорт. Пароль и ключ модели агентам не выдаются. [Подключение агента и инструменты](docs/agent-integration.md), [инструкция для существующей задачи](docs/chatgpt-task-instructions.md). Облачное подключение обоих клиентов доступно после развёртывания и подтверждения OAuth владельцем и требует проверки. Интерактивные MCP Apps пока не реализованы.

Актуальная версия указана в `package.json` и [GitHub Releases](https://github.com/LeonDeTur/paper-word/releases). [Журнал изменений](CHANGELOG.md) и [порядок выпуска SemVer](docs/versioning.md). Версия в интерфейсе и MCP берётся из `package.json`.

Перед публикацией и настройкой окружения см. [хранение секретов и личных данных](SECURITY.md). Примеры адресов в репозитории нужно заменить своими; реальные настройки хранятся вне Git.
