# Интерфейс Paperword

Личный инструмент ежедневного чтения. Основной экран — библиотека; главное действие — добавить статью. В читалке главный объект — английский текст, затем перевод и действия со словами. В повторении — вопрос, раскрытие ответа и оценка.

Визуальное направление: спокойная редакционная читалка, тёплый светлый фон, зелёный акцент в светлой теме, Georgia для текста статей и крупных заголовков. По уточнению пользователя чёрная тема полностью монохромная: фон #000000, белый текст и серые элементы без цветных акцентов. Образец — реальный HTML Spatial-RAG из прежней задачи с RU / RU ALL. Маркетинговый экран не нужен.

Проверяемые размеры: **1440×900** и **390×844**. На компьютере постоянная боковая навигация; на телефоне нижняя навигация, действия темы и выхода доступны в настройках. Длинные заголовки переносятся. Горизонтальное переполнение отсутствует на проверенных экранах. Основной текст читается в ограниченной по ширине колонке.

Состояния:

- Загрузка: сообщение «Открываем вашу библиотеку…» и индикатор; уменьшение анимации через prefers-reduced-motion.
- Пустая библиотека: объяснение и кнопка добавления первой статьи.
- Ошибка: описание проблемы, сохранённый пользовательский ввод и возможность повторить действие; отдельно проверена недоступность сервера моделей.
- Частичные данные: оригинал доступен при неполном переводе, показано число переведённых фрагментов, отсутствующий перевод обозначен явно.
- Успех: добавленный материал виден в библиотеке; слово доступно в словаре; обе оценки повторения сохраняются.
- Доступ: экран пароля перед личной библиотекой; после выхода приватный API недоступен.

Доступность: нативные кнопки, формы и dialog; подписи полей, видимый фокус, возврат фокуса при закрытии dialog, доступные с клавиатуры действия со словами. Отдельное действие «Слово / фраза» доступно без нажатия на текст. В повторении доступны кнопки и клавиши. Цветовые контрасты проверяются axe на фактически отрисованных экранах; это не полная сертификация доступности.

Локальные скриншоты и наблюдения проверки сохраняются в `artifacts/qa/evidence.json`. Изображения показывают явно обозначенный учебный пример из изолированного теста.
