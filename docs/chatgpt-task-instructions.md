# Пример инструкции для регулярной задачи

Этот блок можно добавить к существующей задаче подготовки переводов. Расписание, правила подготовки HTML и список исключений сохраняются. Заменить `https://paperword.example.com` на свой APP_ORIGIN; идентификаторы личных чатов и сведения о расписании в репозиторий не добавлять.

Подключение MCP-приложения и загрузка из облачного запуска требуют развёрнутого VPS и OAuth владельца.

```text
ЗАГРУЗКА В ЛИЧНУЮ БИБЛИОТЕКУ PAPERWORD:
После подготовки и проверки единственного готового HTML сохрани этот же файл в мой сервис Paperword: https://paperword.example.com. Используй подключённое MCP-приложение Paperword и инструмент import_chatgpt_file. Передай настоящий объект файла ChatGPT (file_id и download_url; при наличии file_name и mime_type), а не путь /mnt/data и не выдуманную ссылку. external_id должен быть устойчивым: DOI или arXiv ID + версия + :bilingual-black. Укажи название статьи, ссылку на научный первоисточник и тематические теги. Не передавай полный HTML через текст инструмента, если доступна передача файла.
Проверь квитанцию: id, translated_blocks, duplicate и reader_url. Только после успешного ответа сообщай, что статья добавлена; добавь ссылку на чтение в Paperword рядом с прежней единственной ссылкой «Скачать — чёрная тема». При необходимости проверь квитанцию через get_imported_article. Повтор после сетевого сбоя должен использовать тот же external_id и тот же готовый файл. При конфликте не перезаписывай имеющуюся статью.
Если MCP-приложение ещё не подключено, сервис недоступен, требуется повторная авторизация или подтверждение записи, сохрани готовый HTML как раньше и коротко укажи, что автоматическая загрузка не выполнена и почему. Не создавай новую автоматизацию, не меняй расписание и не выдавай попытку загрузки за успех. Не проси пользователя передавать пароль Paperword или токены в текст чата.
```

После развёртывания VPS создать приложение в ChatGPT с MCP URL `https://paperword.example.com/mcp`, OAuth и dynamic client registration (если интерфейс предлагает client ID/secret — оставить пустыми для DCR). Доступность пользовательских приложений и их вызовов из расписания зависит от плана и настроек рабочего пространства. Первый вход и подтверждение OAuth выполняет владелец; разрешения на записи определяет ChatGPT. После подключения проверить одним ручным запуском существующей задачи. До этого запуск из облака не считается проверенным.
