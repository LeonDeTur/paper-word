# Управление Paperword через HTTP API и MCP

Сервис предоставляет импорт, поиск и чтение библиотеки, редактирование переводов, управление карточками и повторениями через HTTP API и MCP. Сайт и агенты используют общую логику и SQLite. Доступ предоставляется через OAuth для ChatGPT/Claude или отдельный отзываемый bearer-токен. Права выбирает владелец. Старые токены сохраняют только `articles:import`; права автоматически не расширяются. Пароль владельца, ключ модели и настройки сервера через MCP не выдаются.

## Разрешения

| Scope             | Доступ                                                                      |
| ----------------- | --------------------------------------------------------------------------- |
| `articles:import` | Загрузка статей и квитанции собственных загрузок                            |
| `articles:read`   | Поиск по всей библиотеке, чтение фрагментов и состояния перевода            |
| `articles:write`  | Метаданные статьи, прогресс чтения, сохранение перевода, остановка перевода |
| `cards:read`      | Словарь и очередь повторений                                                |
| `cards:write`     | Создание и редактирование карточек                                          |
| `reviews:write`   | Сохранение оценки пользователя                                              |
| `ai:use`          | Вызов модели, настроенной в Paperword; возможны расходы провайдера          |
| `data:delete`     | Удаление вместе с соответствующим `articles:write` или `cards:write`        |

В настройках можно выбрать «Только импорт», «Управление без удаления» или отдельные права. Удаление по умолчанию выключено и в ручных токенах, и на странице OAuth. Для регулярной задачи, которая только загружает готовые статьи, достаточно `articles:import`. Для чата с полным управлением можно выбрать остальные права. Для запуска перевода нужны `articles:write` и `ai:use`; для подсказки слова — `cards:read` и `ai:use`; для статистики — `articles:read` и `cards:read`.

## Токен и адрес сервиса

Открыть **Настройки → Доступ агента**, выбрать права, задать срок и нажать **Создать токен**. Можно выбрать дату и время в календаре или ввести команду: `30d`, `12h`, `2w`, `15m`, `30 дней`, `31.12.2027 18:00` или `2027-12-31`. Дата без времени означает конец дня; календарные даты трактуются в часовом поясе браузера, который показан рядом с полем. Срок может превышать 365 дней. Скопировать показанный токен в окружение своего агента. На сервере хранится только SHA-256 токена; повторно получить исходный токен нельзя. Кнопка «Отозвать» немедленно прекращает доступ по HTTP и MCP. Для новой интеграции можно выпустить отдельный токен.

HTTP API владельца: `POST /api/agent-tokens` с cookie сессии, `X-Paperword: 1` и JSON `{ "name": "Importer", "scopes": ["articles:import"], "expires_in": 43200 }` (секунды) либо `{ "name": "Importer", "expires_at": "2027-12-31T18:00:00+03:00" }`. `expires_at` требует ISO-дату с часовым поясом. Прежнее поле `days` поддерживается; если срок не передан, используется 90 дней. Допускается только один из `days`, `expires_in`, `expires_at`. Прошедшие, несуществующие и непредставимые даты отклоняются с `422`. Дата окончания сохраняется в UTC и проверяется на каждом запросе. Эти настройки относятся к ручным bearer-токенам; сроки OAuth-подключения описаны ниже. Поле `scopes` необязательно: без него выдаётся только `articles:import`. Чтобы расширить права старого токена, создайте новый токен и отзовите старый.

Далее `PAPERWORD_URL` — адрес веб-сервиса, например `https://papers.example.com`, а `PAPERWORD_TOKEN` — выданный токен. В локальном окружении допустим `http://127.0.0.1:3001`. Удалённому агенту понадобится адрес VPS, доступный из его сети; localhost обозначает компьютер самого агента.

## HTTP: загрузка готового файла

```sh
curl --fail-with-body "$PAPERWORD_URL/api/agent/articles/file" \
  -H "Authorization: Bearer $PAPERWORD_TOKEN" \
  -F 'external_id=arxiv:2606.12821v2:black' \
  -F 'source_url=https://arxiv.org/abs/2606.12821' \
  -F 'tags=["Geospatial AI","Agents"]' \
  -F 'file=@geonatureagent_benchmark_black.html'
```

Поддерживаются HTML, PDF, TXT и Markdown до 15 МБ. Поля: обязательные `external_id` и `file`; необязательные `title`, `source_url` и `tags` (JSON-массив строк). Для файлов с иллюстрациями это предпочтительный способ: исходный файл сохраняется, агенту не нужно передавать мегабайты HTML в контекст модели. Загруженный HTML разбирается как данные, его скрипты не исполняются.

Пример PowerShell без зависимости от curl:

```powershell
$agentHeaders = @{ Authorization = "Bearer $env:PAPERWORD_TOKEN" }
$uploadForm = @{
  external_id = 'arxiv:2606.12821v2:black'
  file = Get-Item -LiteralPath './geonatureagent_benchmark_black.html'
}
Invoke-RestMethod -Method Post -Uri "$env:PAPERWORD_URL/api/agent/articles/file" -Headers $agentHeaders -Form $uploadForm
```

## HTTP: структурированная статья, HTML или ссылка

`POST /api/agent/articles`, заголовки `Authorization: Bearer …` и `Content-Type: application/json`. Предел JSON-запроса — 2 МБ.

```json
{
  "external_id": "my-paper:version-1",
  "title": "My prepared article",
  "source_url": "https://example.com/paper",
  "tags": ["Research"],
  "content": {
    "type": "blocks",
    "blocks": [
      { "kind": "heading", "text": "Abstract", "ru": "Аннотация" },
      {
        "kind": "paragraph",
        "text": "The English paragraph.",
        "ru": "Русский абзац."
      }
    ],
    "dictionary": { "paragraph": "абзац" }
  }
}
```

Вместо `blocks` можно передать `content: {"type":"html","html":"<!doctype html>…"}` или `content: {"type":"url","url":"https://example.com/article.html"}`. Импорт ссылки получает материал с публичного HTTP/HTTPS-адреса; внутренние адреса запрещены. Он **не переводит** английский текст автоматически и не запускает ИИ. Если нужен готовый перевод, агент должен прислать его в HTML или `blocks`.

Ответ содержит `id`, `title`, `source_url`, `tags`, количество `blocks` и `translated_blocks`, признак `duplicate` и `reader_path`, например `/#article/…`.

`GET /api/agent/articles/{id}` возвращает квитанцию импорта, доступную текущему токену. `GET /api/agent/status` проверяет токен и доступность сервиса.

## Безопасный повтор

`external_id` — устойчивый идентификатор материала и версии, например DOI или arXiv ID с версией. Повтор неизменного запроса с тем же `external_id` возвращает ту же статью (`200`, `duplicate:true`). Первый импорт возвращает `201`. Если содержимое или метаданные изменились при прежнем `external_id`, сервис отвечает `409`; для новой версии нужен новый идентификатор. Содержимое существующей статьи не перезаписывается.

Дополнительно одинаковый исходный файл или одинаковое структурированное содержимое не создаёт вторую статью даже при другом `external_id`. Ошибки валидации — `422`, отсутствующий/истёкший/отозванный токен — `401`. Агент должен сохранять `external_id` до первой попытки и повторять тот же запрос после сетевого сбоя. Удаление статьи владельцем удаляет её квитанции; после этого повторная загрузка создаёт новую статью.

## Удалённый MCP

Эндпоинт: `https://papers.example.com/mcp`. Транспорт: **stateless Streamable HTTP**, заголовок `Authorization: Bearer …` обязателен на каждом запросе. Поддерживаются клиенты с настройкой собственных заголовков или bearer-токена; Для ChatGPT и Claude поддержан OAuth с PKCE и динамической регистрацией; старый SSE-транспорт не используется. Для клиентов с ручным bearer-токеном прежний способ сохранён.

Инструменты:

- `import_chatgpt_file`: готовый файл из ChatGPT; объект `file` с обязательными `download_url`, `file_id`, необязательными `mime_type`, `file_name`, а также `external_id` и метаданные статьи. Ссылка должна быть HTTPS и вести на публичный адрес; до 15 МБ. Временная ссылка не сохраняется в БД и не передаётся в квитанцию.
- `import_article`: те же поля, что у JSON HTTP API. Готовые блоки, HTML или публичная ссылка. Повтор безопасен по тем же правилам.
- `get_imported_article`: квитанция по `id` для текущего агента.

MCP не принимает путь к произвольному файлу на VPS. Для больших локальных файлов используйте HTTP multipart или локальный stdio-адаптер ниже.

## Инструменты управления

Помимо трёх инструментов импорта доступны:

| Инструмент                      | Назначение                                                                                               |
| ------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `list_articles`                 | Поиск по названию, тегам, английскому тексту и переводу; фильтры статуса и избранного                    |
| `get_article`                   | Статья по частям: `id`, `offset`, `limit`; без бинарных изображений                                      |
| `update_article`                | `id`, `changes`: название, теги, статус, избранное, позиция чтения                                       |
| `save_translation`              | `id`, `block_id`, `ru`, `expected_ru`: сохранение готового перевода с защитой от перезаписи чужой правки |
| `start_translation`             | Запуск/продолжение фонового перевода настроенной моделью                                                 |
| `get_translation_status`        | Состояние, ошибка и количество переведённых фрагментов                                                   |
| `cancel_translation`            | Остановка после текущего запроса к модели                                                                |
| `list_cards`, `get_card`        | Поиск и чтение словаря; `normalized_query` проверяет точное совпадение начальной формы                   |
| `create_card`, `update_card`    | Начальная форма, перевод, контекст, заметка и ссылка на исходную статью                                  |
| `suggest_word`                  | Предложение начальной формы и перевода через настроенную модель без сохранения                           |
| `list_reviews`                  | Очередь EN→RU, RU→EN или обеих направлений                                                               |
| `review_card`                   | Оценка `again`/`hard`/`good`/`easy` и обязательный `expected_due_at` из очереди                          |
| `get_statistics`                | Размер библиотеки и словаря, очередь, ответы за последние 24 часа                                        |
| `delete_article`, `delete_card` | Удаление с дополнительным правом и точным `confirm_title`/`confirm_lemma`                                |

Клиент видит только инструменты, для которых выданы все необходимые права. Сервер проверяет разрешения и при каждом выполнении. Токен не даёт доступ к API владельца, управлению другими токенами или ключам. HTTP-эквивалент любого инструмента управления: `POST /api/agent/actions/{tool_name}`, Bearer, JSON с теми же аргументами. Ошибки: `403` — недостаточно прав, `422` — неверные аргументы, `409` — дубликат или устаревший перевод/ответ.

Списки принимают `offset` и `limit` (по умолчанию 20, максимум 50), возвращают `items`, `total`, `next_offset`. `get_article` по умолчанию возвращает 5 фрагментов, максимум 20. Объём страницы также ограничивается по размеру; используйте возвращённый `next_offset`, а не вычисляйте его самостоятельно. Большой одиночный фрагмент или карточка возвращается целиком. Порядок очереди — ближайший срок повторения первым; изменение коллекции между страницами требует нового поиска.

Пример запроса:

```sh
curl --fail-with-body "$PAPERWORD_URL/api/agent/actions/list_articles" \
  -H "Authorization: Bearer $PAPERWORD_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"query":"spatial","limit":10}'
```

Перевод можно подготовить самим ChatGPT/Claude и сохранить через `save_translation` без Ollama либо запустить `start_translation` на настроенной в Paperword модели. Фоновый перевод не удерживает MCP-запрос: проверяйте состояние через `get_translation_status`. Повторный запуск во время активного задания отклоняется.

При обучении ассистент показывает вопрос, ждёт ответа или самооценки пользователя и только затем вызывает `review_card`. Не нужно автоматически оценивать непросмотренные карточки. Ответ, уже сохранённый на сайте или в другом чате, даёт `409`; перечитайте очередь. Направления имеют независимые интервалы. Сохранение карточки не сбрасывает интервалы существующих карточек; дубликат начальной формы отклоняется.

## Локальный MCP через stdio

Адаптер получает права из `/api/agent/status` при запуске и предоставляет тот же набор инструментов управления. Все вызовы снова проверяются HTTP API. После замены токена перезапустите адаптер.

Собрать проект: `npm ci`, затем `npm run build`. Запустить адаптер с `node /absolute/path/English-Paper-Translation/build/mcp-stdio.mjs`. Он обращается к HTTP API сервиса и не открывает локальную БД. Токен и адрес передаются через окружение.

Пример конфигурации клиента:

```json
{
  "mcpServers": {
    "paperword": {
      "command": "node",
      "args": ["C:/Projects/paperword/build/mcp-stdio.mjs"],
      "env": {
        "PAPERWORD_URL": "https://papers.example.com",
        "PAPERWORD_TOKEN": "YOUR_AGENT_TOKEN",
        "PAPERWORD_IMPORT_DIR": "C:/Articles"
      }
    }
  }
}
```

При заданном `PAPERWORD_IMPORT_DIR` появляется дополнительный инструмент `upload_article_file`: поля `file_path` (относительный или абсолютный), `external_id`, необязательные `title` и `source_url`. Папка должна находиться на машине, где запущен адаптер. Файлы вне неё, в том числе через симлинки, отклоняются. Без этой переменной локальное чтение файлов не предоставляется. Для агента в контейнере укажите путь внутри контейнера и смонтируйте нужную папку.

## Инструкция для постоянной задачи

После создания готового HTML:

1. Вычислить устойчивый `external_id` из DOI/arXiv ID и версии.
2. Вызвать `upload_article_file` или HTTP multipart с готовым файлом. Если агент располагает только текстом и переводом, вызвать `import_article` с блоками.
3. Проверить успешный ответ: `id`, `translated_blocks`, `duplicate` и `reader_path`. Ошибку не выдавать за успешную загрузку.
4. Вернуть владельцу ссылку `PAPERWORD_URL + reader_path`. При сетевой ошибке повторить тот же запрос; при `401` сообщить, что токен нужно обновить; при `409` не перезаписывать имеющийся материал.

Для ChatGPT используйте инструкцию подключения ниже и [блок для существующей задачи](chatgpt-task-instructions.md). Ручной токен нужен агентам, которые работают через HTTP API или stdio; пароль владельца в задачу передавать не нужно.

## ChatGPT и Claude: OAuth

Адрес MCP: `https://paperword.example.com/mcp`. Развернуть [HTTPS на VPS](vps-https.md), затем создать приложение в ChatGPT → Plugins с этим URL и OAuth. Сервер публикует Protected Resource Metadata в `/.well-known/oauth-protected-resource/mcp` и метаданные авторизации в `/.well-known/oauth-authorization-server`. DCR — `/register`, выдача кода — `/authorize`, обмен и refresh — `/token`, отзыв — `/revoke`. Callback разрешён на документированные адреса ChatGPT и точные `https://claude.ai/api/mcp/auth_callback`, `https://claude.com/api/mcp/auth_callback`; локальные callback доступны лишь вне production. В Claude: Customize → Connectors → Add → Custom → Web; тот же MCP URL, вход OAuth и «Register automatically». Режим опубликованной идентификации клиента CIMD не реализован: используйте DCR. Создайте отдельное подключение для каждого клиента.

Войти в Paperword своим паролем и выбрать разрешения на отдельной странице. Удаление выключено по умолчанию, даже если клиент его запросил. Выдать больше прав, чем запросил клиент, нельзя; для расширения нужно подключить интеграцию заново. Пароль в ChatGPT не передаётся. Требуется PKCE S256, точный resource `/mcp` и явно выбранные права; код живёт 5 минут, access token — час, refresh token — 90 дней с заменой при каждом использовании. Повторное использование старого refresh-токена отзывает подключение. Общее разрешение истекает через год. В БД сохраняются хеши токенов. Отзыв в настройках немедленно закрывает OAuth-доступ и ручной доступ данного агента.

Инструмент `import_chatgpt_file` объявляет `_meta["openai/fileParams"] = ["file"]` по контракту ChatGPT. Файл скачивается на VPS по временной HTTPS-ссылке с закреплённым DNS, проверкой каждого редиректа и пределом 15 МБ. Исходные байты идут через тот же импорт, что multipart. Метаданные и хеш исходного файла определяют повтор; смена временной ссылки не создаёт дубликат. HTTP-эквивалент — `POST /api/agent/articles/chatgpt-file` с тем же JSON.

Проверка локальной реализации OAuth и MCP не означает, что облачное приложение уже подключено. Требуется доступный VPS, подтверждение OAuth владельцем и проверка записи из существующей регулярной задачи. Если ChatGPT требует подтверждать запись, его нельзя обойти серверным флагом readOnlyHint.

Контракты: [OpenAI authentication](https://developers.openai.com/plugins/build/auth), [передача файлов и метаданные инструментов](https://developers.openai.com/plugins/reference).

### Передача файлов из Claude и интерфейс в чате

`import_chatgpt_file` использует специальный контракт файлов ChatGPT; наличие этого инструмента не означает, что Claude автоматически выдаст такую же ссылку на своё вложение. В Claude можно передать подготовленные текстовые блоки/HTML через `import_article`, публичную ссылку на материал или использовать локальный stdio-адаптер для файла. Для больших файлов надёжный общий путь — HTTP multipart.

Инструменты возвращают текст и структурированные результаты. Встроенные интерактивные компоненты MCP Apps пока не реализованы. Пользователь может работать командами в чате и переходить по ссылке к полной статье на сайте. Фактическое облачное подключение каждого клиента, передачу файлов и регулярную задачу необходимо проверить после развёртывания HTTPS.
