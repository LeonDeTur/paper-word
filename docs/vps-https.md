# HTTPS для собственного VPS

Пример адреса: **https://paperword.example.com**. MCP: **https://paperword.example.com/mcp**. Заменить их на свой домен. Для бесплатного имени sslip.io можно использовать `paperword.<IPv4-с-дефисами>.sslip.io`; например, `paperword.203-0-113-10.sslip.io`. Адрес `203.0.113.10` зарезервирован для примеров и не является адресом рабочего сервера.

sslip.io автоматически возвращает IPv4, указанный в имени. Это бесплатное DNS-имя стороннего сервиса без регистрации, а не собственный домен `.ru`. [Описание и HTTPS](https://nip.io/). Регион VPS не ограничивает выбор имени; доступность DNS нужно проверить из используемой сети. При смене IP изменится и имя.

В Compose уже есть Caddy: он получает публично доверенный сертификат и продлевает его автоматически. [Automatic HTTPS](https://caddyserver.com/docs/automatic-https). Chrome должен открывать именно имя из сертификата, а не `https://203.0.113.10`. Самоподписной сертификат не удовлетворяет требованию открытия без предупреждений и не используется.

На VPS с установленными Docker и Compose:

```sh
cp .env.vps.example .env
# Открыть .env и указать уникальный APP_PASSWORD минимум из 12 символов.
# Настроить AI_BASE_URL, AI_MODEL и при необходимости AI_API_KEY.
docker compose up -d --build
docker compose logs --tail=80 caddy
```

В firewall VPS и панели хостинга разрешить входящие TCP 80 и 443. Порты должны быть свободны; не запускать второй веб-сервер на них. Для получения сертификата VPS должен быть доступен извне и иметь исходящий HTTPS. Том `caddy_data` содержит состояние и ключи сертификатов — сохранять его между обновлениями. Выпуск и проверка сертификата происходят на VPS после запуска, локальная сборка не подтверждает их успех.

Проверка с другого компьютера, без отключения TLS-проверки:

```sh
curl --fail https://paperword.example.com/api/config
curl --fail https://paperword.example.com/.well-known/oauth-protected-resource/mcp
curl -i -X POST https://paperword.example.com/mcp
```

Первые два запроса должны вернуть JSON; последний — `401` с `WWW-Authenticate` и ссылкой на OAuth-метаданные. После этого открыть сайт в Chrome: ошибки TLS быть не должно. Не использовать `curl -k` для такой проверки.

Если выпуск упирается в лимит общего DNS-провайдера, можно сменить имя на `paperword.203-0-113-10.nip.io` (обновить вместе APP_DOMAIN, APP_ORIGIN и адрес приложения в ChatGPT) либо получить отдельное имя [DuckDNS](https://www.duckdns.org/). Это альтернативы, а не автоматический failover.

Возможен и сертификат непосредственно на IPv4: Let's Encrypt объявил общую доступность IP-сертификатов в январе 2026 года; срок — около шести дней, требуется совместимый ACME-клиент и автоматическое продление. [Официальное объявление](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability). Текущая конфигурация использует обычный сертификат на DNS-имя.

Если нужно перенести две уже загруженные статьи, остановить локальный сервер, сохранить целиком каталог `data`, запустить Compose, остановить `app` и скопировать каталог в `/app/data` через `docker compose cp data/. app:/app/data/`, затем запустить `app`. Сначала сделать резервную копию тома VPS: копирование заменяет совпадающие файлы. Проверить владельца файлов в томе: контейнер работает как `node` (UID 1000). При необходимости восстановить владельца через разовый контейнер Compose с `--user root`, затем запустить сервис.
