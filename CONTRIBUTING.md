# Локальная разработка Paperword

Нужен Node.js **24.14.0 или новее**. Точная минимальная версия записана в `.node-version` и `.nvmrc`; `engine-strict` запрещает установку на неподдерживаемый Node. Docker нужен только для проверки образа и развёртывания. Для обычной разработки достаточно Node.

```sh
npm ci
npm run setup
npx playwright install chromium
npm run dev
```

`setup` создаёт `.env` из примера, только если файла ещё нет, и включает локальные Git hooks. Существующие настройки и пользовательские данные не перезаписываются. Если уже настроен другой `core.hooksPath`, установщик остановится с объяснением. В CI hooks не устанавливаются. На Linux для браузерных системных библиотек используйте `npx playwright install --with-deps chromium`.

Интерфейс: `http://127.0.0.1:5173`, API: `http://127.0.0.1:3001`. Для второго экземпляра задайте другой `PORT` и `DB_PATH`. Тесты используют отдельные порты 3012/3013, БД в памяти/временной папке и макет модели; реальные статьи, ключи и Ollama им не нужны.

## Команды

| Команда                        | Назначение                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------------- |
| `npm run check`                | Версии, приватные файлы, формат, линтер, сборка, все серверные и tooling-тесты     |
| `npm run check:all`            | То же плюс браузерные сценарии                                                     |
| `npm run test:unit`            | Парсинг файлов, ограничения адресов, алгоритм повторений                           |
| `npm run test:integration`     | Express/SQLite, вход, HTTP API, OAuth, MCP HTTP и stdio, миграции, модель-макет    |
| `npm run test:tooling`         | Подготовка версий/changelog в временных Git-репозиториях и защита приватных файлов |
| `npm run test:coverage`        | Все серверные/tooling-тесты и LCOV в `coverage/lcov.info`                          |
| `npm run test:e2e`             | Chromium: компьютер, телефон, тёмная тема, OAuth и доступность                     |
| `npm run test:e2e:ui`          | Интерактивный запуск Playwright                                                    |
| `npm run test:e2e:report`      | HTML-отчёт последнего запуска                                                      |
| `npm run typecheck`            | TypeScript без сборки                                                              |
| `npm run lint`                 | Oxlint без предупреждений                                                          |
| `npm run format`               | Форматирование Prettier                                                            |
| `npm run format:check`         | Только проверка формата                                                            |
| `npm run check:privacy`        | Проверка отслеживаемых файлов на приватные пути и известные форматы ключей         |
| `npm run release -- --dry-run` | Предпросмотр версии и changelog без изменения файлов                               |
| `npm run release:pack`         | Архив собранного приложения и SHA-256 в `release-assets/`                          |

TypeScript проверяет типы отдельно от Oxlint. Правила React Hooks включены; ограничения React Compiler на эффекты, refs и чистоту пока выключены, поскольку проект не использует React Compiler. React-компоненты проверяются браузерными сценариями; LCOV показывает покрытие загруженных серверных модулей и утилит, а не покрытие интерфейса.

По умолчанию используется установленный Playwright Chromium. Для проверки в локальном Google Chrome можно задать `PLAYWRIGHT_CHANNEL=chrome`. Конфигурация не переиспользует чужой тестовый сервер, чтобы случайно не запустить тесты на личной библиотеке. `.only` в CI запрещён, неуспешный браузерный тест повторяется один раз, trace сохраняется при сбое.

## Git hooks и Conventional Commits

- `pre-commit`: проверяет приватные пути/форматы ключей и формат **содержимого индекса**, включая частично добавленные файлы; затем проверяет типы. Ничего автоматически не исправляет и не добавляет в индекс.
- `commit-msg`: проверяет Conventional Commits через Commitlint.
- `pre-push`: запускает `npm run check`. Полный браузерный набор выполняется в CI; локально его можно запустить через `check:all`.

Ветки: `feat/reader`, `fix/import`, `ci/checks`, `chore/release`. Коммиты и заголовки PR: `feat(reader): add a glossary`, `fix(import): preserve paragraphs`, `ci: test Docker builds`. Можно писать описания по-русски. Для несовместимых изменений используйте `feat(api)!: ...` или футер `BREAKING CHANGE: ...`. Заголовок — до 120 символов.

Предпочтителен squash merge с осмысленным Conventional Commit заголовком PR. CI также проверяет сообщения коммитов внутри PR. Автоматизация не переписывает вашу историю и не придумывает смысл изменений: качество примечаний к релизу зависит от описаний коммитов. Для исправления последнего локального сообщения используйте обычный `git commit --amend`; опубликованную общую историю не переписывайте.

Проверки приватности — дополнительная защита известных форматов, а не доказательство отсутствия всех возможных секретов. БД, статьи, `.env`, ключи, отчёты и release assets исключены из Git. Пример конфигурации не должен содержать реальный адрес VPS или учётные данные.
